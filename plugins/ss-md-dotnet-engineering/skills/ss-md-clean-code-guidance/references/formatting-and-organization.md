## Formatting and organization

Formatting should reveal structure, not impose an unrelated personal style.

- Follow the repository's formatter, lint rules, and established layout. Use automated tools where the project provides them.
- Use spacing and indentation to make nesting and relationships clear. Keep related statements together and distinct concepts visually separate.
- Keep code organized so readers can find the important behavior without navigating unrelated details.
- Extract a function, type, or module when it clarifies a real conceptual boundary. Do not treat whitespace or line-count changes as a substitute for meaningful structure.
- Avoid formatting-only churn in a behavior-focused change unless formatting is required by project tooling or needed to make the edited code understandable.
